## 卡住的地方
- `odm_tsc`（pid 1811，服务名 ztethp，跑 `/vendor/bin/odm_tsc` + `libgdix_tsa.so`）持续报：
  `E/[gdix_tsa][ParseFramedata]: uwFrameIndex error, start:28619, end:28620`
  `E/[gdix_tsa][TsaProcessingFrame]: Framedata process fail...`
  `E/[gdix_tsa][UpdateFrameMissingFlag]: frameidxcheck - Missing frame, curFrameIdx(28620), lastFrameIdx(28618)`
- 帧号序列 28619 → 28628 → 28638 → 28650 → 28672，缺口 9/10/12/22，即**丢帧**，不是索引算错。
- HAL 侧：`[GF_HAL][FingerprintCore][enrollTimerThread] enter` → 40 秒后 `[cancel] enter` → `notifyErrorInfo err code : 3`（TIMEOUT）。
- 反汇编确认：`ParseFramedata` 拿帧头 14 字节，用位移 0xc 的 u16 与 `LibMemSumU8(头部,12)` 比对，不等就返回 1 并打 `uwFrameIndex error`。
  也就是说**帧头校验和本身不匹配**，属于数据完整性/时序问题，不是逻辑判断。
